# 版本迭代与维护

当前版本：**0.2.0 Preview**。产品版本的唯一输入是根目录 `package.json` 的 `version`；界面从该文件读取版本，不手写第二套显示版本。

## 如何选版本号

| 变更 | 规则 | 例子 |
| --- | --- | --- |
| 修复缺陷、界面细节、兼容性修正 | PATCH：最后一位加一 | 0.2.0 → 0.2.1 |
| 增加可独立使用的功能 | MINOR：中间一位加一，末位归零 | 0.2.1 → 0.3.0 |
| 稳定版出现不兼容的公开接口或文件语义变更 | MAJOR：首位加一，其余归零 | 1.4.2 → 2.0.0 |
| 测试版本 | 显式版本号，使用 beta/rc 后缀 | 0.3.0-beta.1 → 0.3.0-rc.1 |

0.x 为预览阶段。此阶段的不兼容变更也提升 MINOR，并在更新记录中说明迁移步骤；首次稳定发布为 1.0.0。补丁版不引入不兼容的数据语义。已经发布的版本不修改其标签，后续修复发布新版本。

本次从 0.1.0 升至 0.2.0，是因为工具从只读查看扩展到编辑、删除、颜色标记与保存。

## 同步版本的唯一推荐命令

```powershell
npm run version:bump -- patch
npm run version:bump -- minor
npm run version:bump -- major
npm run version:bump -- 0.3.0-beta.1
```

每次只执行符合本次变更的一条。加 `--dry-run` 可先查看目标版本及将更新的文件。

脚本同步 `package.json`、`package-lock.json`（包括根包）、`Cargo.toml` 的工作区版本、`Cargo.lock` 的两个工作区包以及 `src-tauri/tauri.conf.json`。随后为 `CHANGELOG.md` 写入同版本的日期、功能、修复和迁移说明。依赖锁文件中的第三方包版本不随产品版本变化。

```powershell
npm run check:version
.\scripts\test.ps1
```

版本检查会验证上述版本、更新记录和可选的 `v<版本>` 发布标签。检查失败时应修复版本或更新记录；不要跳过 CI 校验。

## Git 工作与发布流程

1. 每批功能或修复建立独立分支，例如 `codex/csv-editor-0.2.0`，保持提交范围可审查。
2. 提交信息使用 `feat:`、`fix:`、`docs:`、`test:`、`refactor:`、`chore:` 前缀。一次提交只描述一组相关变更，不混入缓存、发行包或其他未完成的工作。
3. 完成实现、更新记录及版本同步，执行前端、Rust 和真实桌面回归。纯文档修改无需重新运行大文件性能测试。
4. 将分支推送并合入 `main`。普通分支/PR 的 Actions 运行检查并生成临时发行包。
5. 在确认通过的发布提交上创建附注标签，推送标签后自动打包并创建 GitHub Release。

以本次版本为例：

```powershell
git push -u origin codex/csv-editor-0.2.0
# 合并到 main 并更新本地 main 后：
npm run check:version -- v0.2.0
git tag -a v0.2.0 -m "CSVScope 0.2.0: CSV editing and cell markings"
git push origin v0.2.0
```

发布标签必须指向已经包含版本号和更新记录的提交。`v0.2.0` 与 `0.2.0` 一一对应；有 `-beta`/`-rc` 的标签会作为预发布。不要用强推覆盖已发布标签。便携包、安装器、日志、基准数据和工具链保留在忽略的目录，不提交到 Git。

## 产品版本、缓存版本与颜色格式版本

产品版本与数据格式分别管理。Rust 的 `FORMAT_VERSION` 只在基础缓存格式或解释方式不兼容时递增；正常功能或补丁升级不强制清除缓存。颜色配套文件目前为 `version: 1`，包含输出 CSV 的 BLAKE3 指纹、表头和分隔符设置及输出后的记录/列 ID。只有改变这个结构或解释方式时才提升颜色格式版本，并实现迁移或明确拒绝旧格式。

CSV 是文本表格，不能在内部存颜色。移动或备份标色文件时同时保留 CSV 和它的 `.csvscope.json` 文件；外部修改 CSV 或用不匹配的解析设置打开时，应用会忽略旧颜色并提示，避免把标记附到错误记录。

编辑状态暂存在当前标签，关闭前应另存为。另存为默认保存全部记录和全部保留列，包含隐藏列；也可明确选择当前筛选结果或仅可见列。保存采用新文件名；源文件保留不变。每次最多编辑/标色/复制 100,000 个单元格，文本编辑和颜色状态合计最多 16MiB；达到预算后请保存并重新打开输出文件继续。
