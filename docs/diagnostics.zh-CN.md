# 运行日志与卡顿排查

从 0.1.1 起，桌面版自动生成本地 JSON Lines 日志。每行是一条完整 JSON，包含毫秒 Unix 时间戳 `timestampUnixMs`、级别、事件名、进程和线程编号，以及操作上下文。

## 日志位置

便携版优先写入 `csvscope.exe` 同目录的 `logs` 文件夹。点击窗口右上角“打开运行日志”可打开实际使用的目录。

若程序目录不可写，依次回退到 `%LOCALAPPDATA%\io.github.tongjixyz.csvscope\logs` 和 `%TEMP%\CSVScope\logs`。可通过环境变量 `CSVSCOPE_LOG_DIR` 指定位置。目录回退原因记录在 `app_start` 中。

正常日志名为 `csvscope-<启动毫秒时间>-<进程号>-<分段号>.log`，每个文件约 5 MiB，保留最近 10 个普通日志文件；其他运行实例正在使用的日志不会被删除。Rust 异常另有 `panic-*.log` 紧急副本。

日志只写入本机，不自动上传。常规上下文只记录文件路径、任务编号、行列数量、阶段与耗时，不记录 CSV 单元格内容或筛选关键字；错误消息可能包含相关文件路径和解析信息。

## 记录内容

- 启动版本、程序路径、缓存目录和内存/线程预算。
- 打开文件、筛选、撤销重做、切换文件、加载分页、候选菜单、缓存管理及导出的开始、完成、耗时与错误。高频状态轮询和分页在正常快速完成时不逐条记录，慢于一秒或失败时才记录。
- 后台准备、查询、候选与导出任务，以及等待工作槽位和数据库连接的耗时。
- 每约 30 秒记录一次进度。耗时超过五秒的在途操作会出现在后续状态记录中。
- 独立线程检查原生窗口心跳和前端心跳：原生窗口连续约五秒或可见前端连续约十秒无心跳时记录 `ui_unresponsive`，恢复后记录 `ui_recovered`。前端恢复后还会记录事件循环延迟。
- 前端未捕获异常、未处理 Promise 拒绝、界面操作错误，以及 Rust panic 和可取得的回溯。

日志通过有界队列交给独立线程写盘，队列拥堵时记录丢弃数量，不等待磁盘。卡顿监测只尝试读取引擎锁；读取不到会记下 `lockBusy`，避免监测本身一起卡住。

## 再次卡住时

记下大致发生时间、操作（如打开文件、排序或关闭标签）和文件大小。即使暂时无响应，也可直接从资源管理器复制 `logs`；恢复或重启之后保留卡住前后所有日志，以及 `panic-*.log`（若有）。原始数据无需一起提供。

普通运行日志不等同于线程转储。若只看到长时间在途操作而无法确定更细的原生调用，下一步可针对该次故障补充 Windows 进程转储。

## 2026-11-20 旧版事件

旧便携版 `csv-workbench.exe` 在本机时间 00:36:52 被 Windows Error Reporting 记为 `AppHangTransient`，随后自行恢复。该版本没有持久化操作日志，不能根据这条系统事件确定具体是哪一条业务操作阻塞。代码检查发现多项同步 IPC 命令会在界面线程访问磁盘或等待引擎锁；0.1.1 将它们移入工作线程，并限制前端状态轮询为同一时刻一个请求。
