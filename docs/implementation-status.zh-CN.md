## 已实现的运行闭环

Windows x64 原生桌面程序，采用 Tauri 2、Rust、React 18、Glide Data Grid 和原生嵌入式 DuckDB。前端资源与查询引擎随应用分发；使用系统 WebView2。运行时不需要 Node、Rust、Vite 或数据库服务。

## 资源策略与基线差异

当前只有一个应用级 DuckDB 实例，所有文件共用 2GiB 的引擎 `memory_limit`、最多 4 个查询线程和 1 个重任务名额。导入、筛选/排序、候选构建和导出共享准入；活动标签优先。后台标签保留轻量状态，前端显示页全局限为 20 页，最多 2 个显示页 IPC 请求在途。

`memory_limit` **不等于整应用内存上限**，解析器、Arrow、Rust、WebView2 以及引擎的部分分配在其外。当前没有进程树硬内存限制或自适应压力监控，不能承诺任何数据形状都低于固定内存值。

磁盘初始上限为总缓存 64GiB、结果/候选 16GiB、引擎临时 16GiB，保留固定 4GiB 可用空间；基础缓存受总上限及 LRU 约束，尚未单独实施设计中的 32GiB 分区。安全余量尚未实现“卷容量 5%”部分。缓存与结果配额错误会结束任务并反馈，不把部分数据标成完整结果。

历史按标签限制，并在全局超过 32MiB 时轮流裁剪旧历史节点；当前生效状态本身不被淘汰。筛选/排序部分最多 4MiB，文本修改/删除/颜色部分合计最多 16MiB。前端每次最多编辑、标色或复制 100,000 个单元格，删除每次最多 100,000 行；超过预算应保存并重新打开输出文件后继续。解析批次按文件受限，后台预览数量由 16 标签上限约束；尚未实现独立的跨标签解析字节令牌池。

常规显示路径截断超长文本，并按当前可见列及有限预取列读取。巨大字段仍可能增加原生 Arrow 批次内存；每字段默认 8MiB、记录 16MiB、2048 列是拒绝超限的保护，不代表允许尺寸内的所有极端组合都完成了内存验收。

## CSV 方言与数据保真

成熟 `csv-core` 增量解析，不按逗号或物理换行简单拆分。UTF-8/BOM、GBK/GB18030，逗号、分号、Tab 均有明确设置；识别仅基于有限样本，用户可以重新指定后重新打开。GBK/GB18030 采用 `encoding_rs` 的 WHATWG 映射，不声称 GB18030-2022 认证兼容。为避免多字节歧义，GBK/GB18030 不接受竖线分隔符。

所有字段先保存文本。空字段和引号内空字符串均为空文本；空白字符串保留；字面量 `NULL` 不转空。完全空的物理行遵循解析库的跳过行为。缺失或额外字段、非法编码及尺寸超限定位后停止；不静默跳过坏记录。重复、空和无表头使用内部唯一列 ID。

当前沿用解析库宽松的引号方言，**没有严格 RFC 引号错误验证器**。错误定位提供逻辑记录号与字节位置，物理行不作为稳定记录身份。

另存为保持未编辑字段文本、已编辑字段的新值及字段内换行；统一 CRLF 记录终止符，不保持源文件的引号选择、BOM 等字节表现。数值或日期解释只用于查询。颜色存储在 `.csv.csvscope.json` 配套文件中，内容指纹、表头及分隔符均匹配时才加载；CSV 本身不写入样式或应用私有内容。

## 已知限制与待验收

| 项目 | 当前边界 |
| --- | --- |
| 16GB 与 Win10 | 当前实际机器为 32GB / Win11；16GB、Win10、全新系统安装未执行 |
| 性能统计 | 单次样本，OS 文件缓存未控制；没有 P95、受控 OS 冷缓存结果 |
| 故障注入 | 磁盘写满、OOM、强杀后各阶段恢复、损坏缓存自动修复尚未完整验收 |
| 缓存复用速度 | 强验证仍需要顺序读取完整源文件，首屏预览不等待；未实现可信变更令牌快验 |
| 源文件变化 | 准备时使用稳定 Windows 读取句柄；就绪后轮询元数据；同大小同时间的改动在下次强验证识别 |
| 导入恢复 | 失败或取消后重新开始，不持久化断点续导 |
| 不可用已选值 | 保留全部条件；前 100 个显式值做上下文可用性查询，其余明确标记未检查，不静默删除 |
| 高级条件 UI | 单列同时提供一组高级条件与值选择；后端支持条件列表，界面未暴露任意布尔表达式编辑 |
| 会话持久化 | 标签切换保留状态；退出应用后不自动恢复标签、布局及历史 |
| 大行号窗口 | Glide 使用有限的 200,000 行移动窗口；跨窗口/远跳清除选区，避免复制到错误绝对记录 |
| 损坏缓存 | 自动修复未完整覆盖，可能需要关闭文件后清理未使用缓存并重新打开 |
| 发布 | 本地预览发行物未签名。常规和离线 NSIS 均已构建并检查资源清单，尚未在干净 Windows 执行安装 |
| 编辑边界 | 暂不插入行列、执行公式、直接覆盖源 CSV；修改保留在标签中，另存为新文件。颜色依赖配套文件 |
| 其他范围 | 追尾、跨文件 SQL、macOS/Linux 发布未实现 |

## Windows x64 发行物

`artifacts/` 中提供便携 ZIP、常规 NSIS 安装器及离线 NSIS 安装器。便携目录含应用本地 MSVC 运行库、第三方许可和 SHA-256 文件清单。真实桌面回归使用该目录中的 EXE。

以下安装器尺寸来自 **0.1.0** 的历史验收，不代表 0.2.0 发行文件尺寸：常规安装器为 13,453,353 字节，缺少 WebView2 时运行微软引导程序。离线安装器为 231,356,865 字节，使用 Tauri 生成的 NSIS 安装脚本的离线分支，嵌入 215,116,512 字节的 Microsoft x64 独立运行库安装程序。该运行库的 Microsoft Corporation Authenticode 签名在打包前已验证。应用和两个安装器的代码签名仍待完成。

## 后续开发优先级

1. 在目标 16GB 机器执行缓存矩阵和重复性能采样；依据失败案例调整默认资源预算。
2. 完成磁盘满、强杀、损坏缓存、超长字段、快速开关标签和导出取消的故障注入。
3. 验证干净 Windows 的 MSVC/WebView2 部署与离线安装，再考虑代码签名。
4. 完善全局解析字节预算、内存压力监控及缓存损坏自愈。
5. 根据真实数据决定严格 CSV 方言、可靠文件变更快验和少数热门列索引，不提前引入第二套引擎或自研表格绘制器。
