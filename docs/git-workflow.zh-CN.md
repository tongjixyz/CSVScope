# 多对话开发与 Git 备份

每个并行任务使用独立工作树和 `codex/` 分支。当前日志修复分支为 `codex/portable-diagnostics`，版本为 `0.1.1`；编辑功能任务可以继续在自己的 `0.2.0` 分支中开发。工作树隔离代码、索引和当前分支，避免在同一目录切换分支或暂存其他任务的修改。

一个版本完成后，先确认版本号一致、相关测试通过，再逐个暂存属于该任务的文件，创建清晰的提交，推送自己的 GitHub 分支并核对远端提交编号。代码推送用于源码备份；发行包是否生成以 GitHub Actions 的实际结果为准。

经过验证的版本可建立 `v<版本号>` 标签触发现有发行工作流。推送标签前先检查远端是否已有同名标签；不覆盖或强制移动标签。

不同任务合并前，需要检查同一文件、版本号及新功能之间的兼容性。尚未验证的编辑功能不应混入维护版。各分支的日志说明、验证记录与提交信息应保留，便于后续审查和合并。

日志、现场快照、测试数据和便携包保持在 Git 忽略的目录中，源码备份不包含运行数据。
