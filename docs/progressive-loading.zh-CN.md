# 渐进加载与读取优化

分支：`codex/progressive-csv-loading`。日期：2026-11-20。

本文保留第一轮渐进浏览的实现与测量记录。2026-11-22 的后续实现已增加导入期间的增量筛选、部分候选与解析/写入流水线，当前行为见 `incremental-filtering.zh-CN.md`。

原流程先显示最多 200 条记录，之后一直停留在该预览，直到完整 CSV 导入完成。新流程在首批事务提交后开放原始顺序的分页读取，后续每批提交都会增加可浏览行数。表格继续按需加载可见行列，不把已读取的全部数据复制到前端内存。

## 加载期间的操作

| 操作 | 行为 |
| --- | --- |
| 滚动、跳转 | 可以访问已提交的记录；跳到尚未读取的位置时提示继续等待 |
| 查看、复制 | 读取完整原字段；表格显示仍截断长文本，复制及单元格详情不截断 |
| 隐藏、调整、固定列 | 加载期间可操作，加载完成后保留布局和浏览位置 |
| 筛选、排序、撤销及重做条件 | 提前设置；加载期间表格保持原始顺序，全量就绪后执行条件 |
| 全量候选、编辑、删除、标色、另存为 | 完整加载后开放 |
| 取消、解析错误 | 停止后台任务，使部分分页失效，不发布不完整的基础缓存 |

首屏预览仍有记录数和字节预算。复用已有缓存时，完整内容指纹校验仍必须通过，随后才开放缓存中的完整数据。

## 实现

解析器把已解码字段直接交给 Arrow 字符串构建器。UTF-8 字段借用解析缓冲，省去每个字段的中间 `String` 分配和每行字符串向量；GBK/GB18030 仍使用原有严格解码规则。列宽校验、字段和记录预算、物理行定位、引号内换行和内容指纹保持原有语义。

后台导入优先提交首屏记录；后续批次沿用 8MiB 字段数据或 32,768 行的上限。每次事务提交后才发布 `loading` 查询的可读行数，`exactTotal` 保持为空。分页、完整字段与复制共用受互斥保护的导入连接，避免读取未提交数据或与缓存移动竞争。

完整加载后切换到正常查询，提前设置的筛选和排序覆盖整个文件。取消或坏记录会撤销当前事务、关闭导入连接并清理未发布的临时目录。

## 本机实测

数据为 `.bench/regular-1g.csv`，实际 1,073,741,973 字节，6,509,896 行、12 列。均为 release 构建，每次导入使用独立的新应用缓存目录；未控制操作系统文件缓存、其他系统负载和 CPU 频率。

最后一次按旧版、新版顺序执行的对照同时采集进程 CPU 时间：

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 原生完整读取 | 30.680 秒 | 23.453 秒 |
| CLI 进程累计 CPU 时间 | 35.375 秒 | 27.094 秒 |
| 第 201 行开始的 256 行可读取 | 完整读取后 | 打开后 0.085 秒，当时已提交 32,968 行 |

这一次对照的完整读取耗时减少 23.56%，累计 CPU 时间减少 23.41%。CPU 时间是全部原生线程的累计值，可能大于墙钟时间。

独立运行的完整读取耗时为旧版 16.919 和 31.099 秒，新版 24.994 和 25.951 秒。机器状态存在较大波动，最后一组差异仅代表该次配对观测。原始记录及二进制 SHA-256 保存在本机。

真实桌面使用同一文件、独立的新应用缓存目录验证：

| 指标 | 结果 |
| --- | --- |
| 首次实际显示数据 | 打开后 0.942 秒 |
| 后台读取时跳至第 1,000 行并实际绘制 | 打开后 1.626 秒，完整字段与复制核对一致 |
| 上述交互前后的后端可读记录数 | 426,184 → 655,560，状态均为准备中，总行数未宣称完成 |
| 完整准备观测 | 24.894 秒 |
| 首次完整筛选 | 1.284 秒 / 65,099 行 |
| 全量排序 | 10.927 秒 |
| 排序结果远跳 | 0.231 秒，源记录号核对一致 |
| 查询取消 | 0.008 秒到终态 |
| 页面异常 | 0 |

桌面流程包含全量排序，采样到 7 个应用及 WebView2 进程，Private Bytes 合计采样峰值为 2,592,186,368 字节。原始记录和截图保存在本机。
